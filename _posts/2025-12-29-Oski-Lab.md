# OSKI LAB – Stealc Malware Analysis Using ANY.RUN & VirusTotal

## Category
**Threat Intelligence**

## Malware Information
- **Malware Family:** Stealc
- **MD5 Hash:** `12c1842c3ccafe7408c23ebf292ee3d9`
- **File Type:** Malicious PowerPoint (PPT)
- **Delivery Vector:** Phishing email attachment
- **Email Subject:** *Urgent New Order*

## Tools Used
- **VirusTotal**
- **ANY.RUN Sandbox**

---

## MITRE ATT&CK Tactics Observed
- Initial Access  
- Execution  
- Defense Evasion  
- Credential Access  
- Command and Control (C2)  
- Exfiltration  

---

## 1. Scenario Overview

An accountant received a phishing email titled **“Urgent New Order”**, purportedly from a legitimate client. Upon opening the attached invoice (PPT file), the document displayed false order details. Shortly after, the organization’s SIEM generated an alert indicating the download of a potentially malicious file.

Initial investigation suggested that the PowerPoint attachment was responsible for the malicious activity. This lab focuses on performing a detailed static and dynamic analysis of the file using VirusTotal and the ANY.RUN sandbox to determine its behavior, configuration, and impact.

---

## 2. Question 1: Malware Creation Time

### Objective
Determine when the malware was created to assess its lifecycle and potential campaign reuse.

### Methodology
1. Upload the file to **VirusTotal**.
2. Navigate to the **Details** tab.
3. Examine the **History** section, which contains metadata such as compilation and creation timestamps.

### Findings
- **Creation Time:**  
2022-09-28 17:40:46 UTC


### Conclusion
The malware is **not newly developed**, indicating reuse or redistribution as part of an ongoing or recurring campaign. The gap between creation and detection suggests the malware may have evaded defenses for an extended period.

---

## 3. Question 2: Command and Control (C2) Server

### Objective
Identify the C2 infrastructure used by the malware.

### Methodology
1. In **VirusTotal**, navigate to the **Relations** tab.
2. Review **Contacted URLs** under network activity.

### Findings
- **C2 Server URL:**
http://171.22.28.221/5c06c05b7b34e8e6.php


### Conclusion
This URL serves as the malware’s command-and-control endpoint, enabling the attacker to receive stolen data and issue commands.

---

## 4. Question 3: First Library Requested Post-Infection

### Objective
Identify the first DLL loaded by the malware to understand its functional dependencies.

### Methodology
1. In **VirusTotal**, open the **Behavior** tab.
2. Review **Files Dropped** and loaded libraries during execution.

### Findings
- **First Library Loaded:**
sqlite3.dll


### Conclusion
The use of `sqlite3.dll` suggests the malware leverages SQLite databases, commonly used for storing browser credentials and session data.

---

## 5. Question 4: RC4 Decryption Key

### Objective
Extract the RC4 key used to decrypt base64-encoded configuration strings.

### Methodology
1. Open the sample in **ANY.RUN**.
2. Navigate to the **Malware Configuration** section.
3. Identify encryption parameters used by the malware.

### Findings
- **RC4 Key:**
5329514621441247975720749009


### Conclusion
This RC4 key is used to decrypt embedded configuration data, including C2 addresses and operational parameters, aiding in stealth and obfuscation.

---

## 6. Question 5: MITRE ATT&CK Technique for Credential Theft

### Objective
Identify the main MITRE ATT&CK technique used to steal user credentials.

### Methodology
1. Review the **MITRE ATT&CK** mapping in the ANY.RUN report.
2. Focus on techniques associated with the `VPN.exe` process.

### Findings
- **Technique ID:** `T1555`
- **Technique Name:** *Credentials from Password Stores*

### Conclusion
The malware extracts stored credentials from browsers and other password storage mechanisms, enabling account compromise and lateral movement.

---

## 7. Question 6: Directory Targeted for DLL Deletion

### Objective
Determine which directories the malware cleans up to evade forensic analysis.

### Methodology
1. Analyze the **Process Tree** in ANY.RUN.
2. Locate the `cmd.exe` child process.
3. Review file deletion commands.

### Findings
The malware targets the following paths:
C:\Users\admin\AppData\Local\Temp\VPN.exe
C:\ProgramData\


### Conclusion
By deleting DLLs and executables from these directories, the malware attempts to remove evidence of its execution and hinder post-incident investigation.

---

## 8. Question 7: Self-Deletion Delay

### Objective
Measure how long the malware waits after exfiltration before deleting itself.

### Methodology
1. Inspect the `cmd.exe` process in ANY.RUN.
2. Look for timeout or delay parameters before deletion.

### Findings
- **Self-Deletion Delay:**
5 seconds


### Conclusion
The short delay ensures successful data exfiltration while minimizing the time the malware remains detectable on the system.

---

## 9. Overall Malware Behavior Summary

1. Delivered via phishing email (malicious PPT)
2. Executes embedded payload
3. Loads credential-related libraries
4. Decrypts configuration using RC4
5. Communicates with external C2 server
6. Exfiltrates stolen credentials
7. Deletes executables and DLLs
8. Self-destructs after a short delay

---

## 10. Lessons Learned

### 1. Office Documents Remain High-Risk Entry Points
PowerPoint files can still deliver malware effectively, reinforcing the need for attachment sandboxing and macro restrictions.

### 2. Sandbox Analysis Reveals Full Kill Chain
ANY.RUN provides visibility into execution flow, C2 communication, credential theft, and cleanup behavior that static analysis alone cannot reveal.

### 3. Credential Stores Are Prime Targets
The use of `sqlite3.dll` and T1555 highlights how frequently attackers target browser and application password stores.

### 4. Obfuscation Is a Core Evasion Strategy
RC4-encrypted configurations make detection and signature-based defenses more difficult without behavioral analysis.

### 5. Self-Deletion Does Not Mean No Evidence
Even when malware deletes itself, network traffic, memory artifacts, and sandbox telemetry remain valuable for detection and response.

---

## 11. Final Remarks

This analysis demonstrates how Stealc malware leverages phishing, encrypted configuration data, credential harvesting, and rapid self-deletion to compromise victims while minimizing its footprint. Combining **VirusTotal intelligence** with **ANY.RUN behavioral analysis** provides a comprehensive understanding of both the malware’s intent and its operational techniques.
