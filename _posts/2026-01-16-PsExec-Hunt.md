# SMB Traffic Analysis – PsExec Lateral Movement Investigation

## Category
**Network Forensics**

## Tool Used
- **Wireshark**

## MITRE ATT&CK Tactics
- **Execution**
- **Defense Evasion**
- **Discovery**
- **Lateral Movement**

---

## Scenario Overview

An alert generated by the Intrusion Detection System (IDS) indicated suspicious **lateral movement activity involving PsExec**. PsExec is a legitimate Windows administrative tool that is frequently abused by attackers to move laterally within a network using stolen or valid credentials.

As a SOC Analyst, the objective of this investigation was to analyze SMB traffic within the provided PCAP file to:
- Identify the attacker’s initial entry point
- Track lateral movement attempts
- Determine compromised systems
- Extract authentication details
- Identify abused administrative network shares

---

## Investigation Methodology

The analysis focused primarily on **SMB and SMB2 traffic over TCP port 445**, leveraging the following Wireshark techniques:

- **Statistics → Conversations (IPv4)**
- SMB command filtering:
  - `smb.cmd == 0x72`
  - `smb2.cmd == 0x00`
- NTLM authentication filters:
  - `ntlmssp.challenge.target_name`
  - `ntlmssp.auth.username`
- SMB object extraction:
  - `File → Export Objects → SMB`

---

## Q1: Attacker Initial Access Point

### Objective
Identify the IP address from which the attacker initiated SMB-based lateral movement.

### Analysis
By reviewing **IPv4 conversations** and isolating early SMB negotiation traffic, the source IP with abnormal SMB activity was identified.

![](assets/ps/ps1.png)

### Finding
**Initial attacker source IP address:**
```10.0.0.130```


This IP generated the earliest SMB session setup requests and exhibited high-volume SMB traffic consistent with PsExec usage.

---

## Q2: First Pivoted Hostname

### Objective
Determine the hostname of the first machine the attacker pivoted to.

### Analysis
Filtering for NTLM challenge messages using:
```ntlmssp.challenge.target_name```


revealed metadata returned by the target system during the authentication process.

![](assets/ps/ps2.png)

### Finding
**First compromised hostname:**
```SALES-PC```


The NTLMSSP Challenge response exposed:
- NetBIOS computer name
- DNS computer name
- Domain context

This confirms **SALES-PC** as the initial pivot target during lateral movement.

---

## Q3: Compromised Username

### Objective
Identify the account used by the attacker for authentication.

### Analysis
The NTLM Authenticate message was extracted using:
```ntlmssp.auth.username```


This filter highlights the username submitted during SMB Session Setup.

![](assets/ps/ps3.png)

### Finding
**Compromised username:**
```ssales```


The use of a valid internal account indicates **credential compromise rather than brute-force activity**.

---

## Q4: Malicious Service Executable

### Objective
Identify the service executable deployed by PsExec on the target system.

### Analysis
SMB file transfers were reviewed using:
File → Export Objects → SMB



This revealed an executable copied to the target via an administrative share.

![](assets/ps/ps4.png)

### Finding
**Service executable deployed:**
```PSEXESVC.exe```


PsExec copies `PSEXESVC.exe` to the target system to create a temporary service that enables remote command execution.

---

## Q5: Network Share Used for Service Installation

### Objective
Determine which SMB share was used to install the PsExec service.

### Analysis
SMB Tree Connect requests revealed access to a hidden administrative share.

![](assets/ps/ps5.png)

### Finding
**Administrative share used:**
```ADMIN$```


The `ADMIN$` share provides access to the Windows system directory and is commonly abused by attackers with administrative credentials.

---

## Q6: Network Share Used for Communication

### Objective
Identify the SMB share used for communication between attacker and target.

### Analysis
SMB Tree Connect requests showed communication over a special-purpose share.

![](assets/ps/ps6.png)

### Finding
**Communication share used:**
```IPC$```


The `IPC$` share facilitates inter-process communication and remote procedure calls (RPC), which PsExec relies on for command execution and service management.

---

## Q7: Second Lateral Movement Target

### Objective
Identify any additional systems targeted for lateral movement.

### Analysis
Further SMB session attempts revealed another NTLM authentication exchange directed at a different host.

![](assets/ps/ps7.png)

### Finding
**Second targeted hostname:**
```MARKETING-PC```


However, authentication failed with:
```STATUS_LOGON_FAILURE```



This indicates the attacker attempted to pivot further but lacked valid credentials or sufficient privileges on this host.

## Lessons Learned

### 1. Legitimate Tools Can Be Dangerous
PsExec is a trusted administrative utility, but when abused with stolen credentials, it becomes a powerful lateral movement tool. Detection should focus on **behavior**, not just malware signatures.

### 2. NTLM Authentication Leaks Valuable Metadata
Even without cracking credentials, NTLM challenge messages expose:
- Hostnames
- Domain names
- Network structure  
This information significantly aids attackers during reconnaissance.

### 3. Administrative Shares Are High-Risk
Shares such as `ADMIN$` and `IPC$` are essential for Windows administration but are frequently abused during lateral movement. Monitoring access to these shares is critical.

### 4. Credential Hygiene Is Critical
The attack succeeded because a valid account (`ssales`) had sufficient privileges. Enforcing:
- Least privilege
- Strong password policies
- Credential rotation  
can significantly reduce attack impact.

### 5. Failed Lateral Movement Is Still a Warning
Although the pivot to `MARKETING-PC` failed, it confirms the attacker’s intent to expand further. **Blocked attempts are still valuable indicators of compromise**.

---

## Conclusion

This investigation demonstrates how **SMB traffic analysis in Wireshark** can effectively uncover PsExec-based lateral movement. By correlating SMB sessions, NTLM authentication exchanges, and file transfers, we successfully reconstructed the attacker’s actions and identified both compromised and targeted systems.

Continuous monitoring of SMB activity, NTLM authentication, and administrative share usage is essential for detecting and mitigating similar threats in enterprise environments.
