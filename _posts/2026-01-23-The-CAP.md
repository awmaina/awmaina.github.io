# CAP – Linux Privilege Escalation via IDOR and Capabilities

## Difficulty
**Easy**

## Platform
Hack The Box

## Target OS
Linux

---

## Machine Overview

CAP is an easy Linux machine running a web application that exposes administrative functionality for capturing network traffic. Due to **improper access control**, the application suffers from an **Insecure Direct Object Reference (IDOR)** vulnerability, allowing access to other users’ packet captures.

The exposed packet capture contains **plaintext credentials**, which are reused across services. After gaining user-level access, **Linux capabilities** assigned to a binary are abused to escalate privileges to root.

## Lessons Learned
1. IDOR Vulnerabilities Are High Impact

Even simple numeric object references can expose highly sensitive data if proper access controls are missing.

2. Packet Captures Are Extremely Sensitive

Exposing PCAP files without strict authorization can leak credentials, internal IPs, and system details.

3. Plaintext Protocols Are Dangerous

Using protocols like FTP exposes credentials in cleartext, making interception trivial.

4. Credential Reuse Amplifies Risk

Reusing passwords across services (FTP → SSH) allows attackers to escalate quickly after initial compromise.

5. Linux Capabilities Require Careful Management

Granting powerful capabilities such as cap_setuid to common binaries like Python can completely undermine system security.

## Conclusion

The CAP machine demonstrates how multiple low-to-medium risk misconfigurations—IDOR, plaintext credentials, and excessive Linux capabilities—can be chained together to achieve full system compromise. This lab highlights the importance of defense-in-depth, proper access controls, and careful privilege management in Linux environments.
