# Kioptrix Level 4: Penetration Test Write-up

## Introduction
This document details the penetration testing process for Kioptrix Level 4, a vulnerable virtual machine designed for security enthusiasts to practice their skills. The objective was to gain root access to the machine, documenting each phase from initial reconnaissance to privilege escalation.

## Target Information
**Target IP:** 192.168.56.105

![](/assets/kiop/kio41.png)

## Phase 1: Initial Foothold and Reconnaissance

### Nmap Scan
An initial Nmap scan was performed to identify open ports, services, and the operating system. The following command was used:

```bash
sudo nmap -sC -sV -O -p- 192.168.100.105
```

![](/assets/kiop/kio42.png)

**Breakdown of the flags:**
*   `sudo`: Required for OS detection (`-O`) and stealth SYN scans.
*   `-sC`: Runs default scripts, crucial for automatically checking common vulnerabilities like SMB or anonymous FTP login.
*   `-sV`: Service Version Detection, providing exact versions of running services (e.g., Apache, SMB, SSH) for exploit identification.
*   `-O`: Enables OS Detection.
*   `-p-`: Scans all 65,535 ports, as critical vulnerabilities can sometimes be hidden on high ports.

**Scan Results:**

| Port | Service | Version      | Vulnerability Notes                                                                                             |
|------|---------|--------------|-----------------------------------------------------------------------------------------------------------------|
| 22   | SSH     | OpenSSH 4.7p1| Very old; likely used for logging in once credentials are found via other services.                               |
| 80   | HTTP    | Apache 2.2.8 | Running PHP 5.2.4. Look for web applications, login forms, and potential SQL Injection.                         |
| 139/445| SMB     | Samba 3.0.28a| A "vintage" version of Samba, potentially vulnerable to specific exploits or user enumeration.                  |

## Phase 2: Web Enumeration

### Directory Brute-Forcing
A directory brute-force tool, `gobuster`, was used to discover hidden directories and files on the web server.

```bash
gobuster dir -u http://192.168.56.105 -w /usr/share/wordlists/dirb/common.txt
```
![](/assets/kiop/kio43.png)

![](/assets/kiop/kio44.png)

During this phase, the directory `/john` was identified as a significant clue.

## Phase 3: SMB Enumeration

### Confirming Users with SMB
To confirm the existence of the user `john` and potentially discover others, an Nmap script for SMB user enumeration was utilized.

```bash
nmap -p 445 --script smb-enum-users 192.168.56.105
```
![](/assets/kiop/kio45.png)

![](/assets/kiop/kio46.png)

**Verified System Users:** `john`, `loneferret`, `robert`, and `root`. Given the discovery of the `/john` directory earlier, `john` became the primary target.

## Phase 4: Web Vulnerabilities

### Automated Scanning with Nikto
Nikto was run in the background to identify server-side misconfigurations and outdated modules.

```bash
nikto -h http://192.168.56.105
```
![](/assets/kiop/kio47.png)

**Key Findings from Nikto:**

| Finding Type           | Impact                                                              |
|------------------------|---------------------------------------------------------------------|
| `database.sql` File Leak | Potential access to user credentials/DB structure.                  |
| `#wp-config.php#` File Leak | Likely contains database login credentials.                         |
| Apache 2.2.8 Software  | High risk of known CVE exploits.                                    |
| `mod_negotiation` Config | Allows for easier brute-forcing of filenames via MultiViews.        |
| Directory Indexing Config | `/icons/` and `/images/` are viewable, revealing file structures.   |

### SQL Injection (SQLi) - Authentication Bypass
The primary web vulnerability identified was an SQL Injection in the login mechanism, allowing for authentication bypass.

**How the SQLi Works:**
The backend code likely uses a query similar to: `SELECT * FROM users WHERE username = '$user' AND password = '$pass'`

By using the payload `' OR 1=1#`, the logic of the command is altered:
1.  **The Delimiter (`'`):** Closes the string for the field being typed in.
2.  **The Logic (`OR 1=1`):** Adds a condition that is mathematically always true.
3.  **The Comment (`#`):** Deletes the rest of the original query, preventing the database from checking the other field.

![](/assets/kiop/kio48.png)

![](/assets/kiop/kio49.png)

![](/assets/kiop/kio410.png)

**Targeting Valid Users:**
Using the discovered usernames, `john` and `robert`, the following credentials were used to bypass authentication:

*   **Username:** `john`
*   **Password:** `' OR 1=1#`

*   **Username:** `robert`
*   **Password:** `' OR 1=1#`

This allowed successful login for both users.

## Phase 5: Logging into the Machine via SSH and Privilege Escalation

### SSH Access
With valid credentials obtained through SQLi, SSH was used to gain initial access to the machine. The Nmap scan confirmed Port 22 (SSH) was open.

```bash
ssh -oHostKeyAlgorithms=+ssh-rsa john@192.168.56.105
```

**Password:** `MyNameIsJohn`

![](/assets/kiop/kio412.png)

Upon successful login, a warning about the "LigGoat Shell" confirmed that the session was trapped in a Restricted Shell (lshell), designed to prevent standard system commands.

### Breaking Out of `lshell`
The goal was to escape the restricted shell and obtain a full system shell. Since `lshell` often allows the `echo` command and basic Python integration, a Python-based escape was attempted.

```bash
echo os.system('/bin/bash')
```

**Verification:**
Successful execution changed the prompt from `john:~$` to a simpler `$` or `john@Kioptrix4:~$.` This indicated a successful breakout. The freedom was verified by running commands previously blocked:

```bash
whoami

```

## Conclusion
This penetration test successfully demonstrated the process of exploiting various vulnerabilities, including outdated services, web application flaws (SQL Injection), and restricted shell escapes, to gain root access on the Kioptrix Level 4 machine. The exercise highlighted the importance of comprehensive reconnaissance, vulnerability identification, and strategic exploitation techniques in a controlled environment.
